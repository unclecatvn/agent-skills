01 — WhyVì sao

Plausible Odoo code is the expensive kind.

Code Odoo "trông có vẻ đúng" là loại tốn kém nhất.

AI assistants write code that looks right. The failures that cost time are always the same kind:

Trợ lý AI viết code trông có vẻ đúng. Những lỗi tốn thời gian luôn thuộc cùng một kiểu:

✕

Symbols that don't exist

Symbol không hề tồn tại

A field or xmlid the base addon never had: sale.order.delivery_date, sales_team.group_sale_admin.

Field hoặc xmlid mà addon gốc chưa từng có: sale.order.delivery_date, sales_team.group_sale_admin.

✕

Anchors from another module

Anchor của module khác

An xpath on a field only another module adds, so the install fails with "cannot be located in parent view".

Xpath trỏ vào field mà chỉ module khác thêm vào, nên cài module lỗi "cannot be located in parent view".

✕

The wrong hook

Override sai chỗ

An override on the public method instead of the hook that does the work.

Override method public thay vì đúng hook thực sự làm việc.

✕

Data dropped silently

Mất dữ liệu âm thầm

A stored field renamed without a migration: the column and its data are gone.

Đổi tên field stored mà không có migration: cột và dữ liệu của nó biến mất.

✕

sudo() nobody can audit

sudo() không ai kiểm soát

Access checks bypassed with no stated reason and no prior check.

Bỏ qua phân quyền mà không có lý do rõ ràng, cũng không kiểm tra trước.

✕

"Tests pass"

"Test pass rồi"

Exit code 0, when the run ran zero tests because the module wasn't installed there.

Exit code 0, trong khi không chạy test nào vì module chưa được cài trên database đó.

03 — How it worksCách hoạt động

One procedure for every Odoo change.

Một quy trình cho mọi thay đổi Odoo.

odoo-workflow runs before any code is written, and again before anything is called done. A question like "where is X defined?" stops after step 2; a typo fix takes the fast path.

odoo-workflow chạy trước khi viết dòng code nào, và chạy lại trước khi coi là xong. Câu hỏi kiểu "X được định nghĩa ở đâu?" dừng ở bước 2; sửa lỗi chính tả thì đi đường tắt.

04 — Trace helper

It doesn't remember. It checks.

Không nhớ. Mà kiểm tra.

odoo_trace.py parses your Odoo source with Python's ast, follows _inherit mixins, _inherits delegation and the core BaseModel, and prints an absolute file:line. Standard library only. It only reads.

odoo_trace.py phân tích source Odoo của bạn bằng ast của Python, đi theo mixin _inherit, uỷ quyền _inherits và BaseModel của core, rồi in ra file:line tuyệt đối. Chỉ dùng thư viện chuẩn. Chỉ đọc, không ghi.

09 — FAQ

Questions.

Câu hỏi thường gặp.

Is this an Odoo module?Đây có phải module Odoo không?

No. It is instructions for your AI assistant plus a read-only Python helper. Nothing is installed in Odoo, and nothing enforces itself: results depend on the assistant, the model and the checks you let it run.

Không. Đây là hướng dẫn cho trợ lý AI cùng một helper Python chỉ-đọc. Không cài gì vào Odoo, cũng không tự cưỡng chế: kết quả phụ thuộc vào trợ lý, model và những bước kiểm tra bạn cho phép nó chạy.

Does it send my code anywhere?Nó có gửi code của tôi đi đâu không?

The trace helper only reads files on your machine and prints to your terminal. It uses the Python standard library and makes no network calls.

Trace helper chỉ đọc file trên máy bạn và in ra terminal. Nó chỉ dùng thư viện chuẩn của Python và không gọi mạng.

Which Odoo versions?Hỗ trợ những phiên bản Odoo nào?

16.0, 17.0, 18.0 and 19.0, one reference pack each. The version always comes from your core's odoo/release.py, never from a guess.

16.0, 17.0, 18.0 và 19.0, mỗi bản một gói. Phiên bản luôn được đọc từ odoo/release.py của core, không bao giờ đoán.

Isn't it slower?Như vậy có chậm hơn không?

It reads more before it writes: about twice the output tokens and 1.7× the tool calls on the evals. For a label or a typo that's waste, which is why those take a fast path.

Nó đọc nhiều hơn trước khi viết: khoảng gấp đôi token đầu ra và 1,7 lần số lần gọi tool trên các eval. Với một nhãn hay lỗi chính tả thì phí, nên những việc đó đi đường tắt.

Is it free?Có miễn phí không?

Yes, MIT licensed. Issues and pull requests are welcome on GitHub.

Có, giấy phép MIT. Issue và pull request đều được chào đón trên GitHub.
