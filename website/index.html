What is Agent Skills for Odoo?Agent Skills cho Odoo là gì?
A free, open-source toolkit that makes AI coding assistants such as Claude Code, Cursor and Codex work from your real Odoo source instead of from memory: reference packs for Odoo 16 to 19, the odoo-workflow skill with a read-only trace helper, and two agents, odoo-code-tracer and odoo-code-review. It is not an Odoo module: nothing is installed in your database.
Bộ công cụ miễn phí, mã nguồn mở giúp trợ lý AI như Claude Code, Cursor và Codex làm việc từ source Odoo thật của bạn thay vì theo trí nhớ: gói tài liệu cho Odoo 16 đến 19, skill odoo-workflow kèm helper trace chỉ đọc, và hai agent odoo-code-tracer, odoo-code-review. Đây không phải module Odoo: không cài gì vào database của bạn.

Which Odoo versions are supported?Hỗ trợ những phiên bản Odoo nào?
Odoo 16.0, 17.0, 18.0 and 19.0, Community and Enterprise. The version is read from your core's odoo/release.py, never assumed, and the matching pack is loaded. The workflow and its helper are checked against the Odoo 18 and 19 source.
Odoo 16.0, 17.0, 18.0 và 19.0, cả Community lẫn Enterprise. Phiên bản được đọc từ odoo/release.py của core, không bao giờ đoán, rồi nạp đúng gói tài liệu. Quy trình và helper được kiểm tra trên source Odoo 18 và 19.
What do I need on my machine?Cần chuẩn bị gì trên máy?
A local checkout of the Odoo source your project runs, plus enterprise if you use it; Python 3.8 or later for the helper, with only the standard library, so your Odoo virtualenv works; PostgreSQL with the right to create scratch_* databases for the tests; Node.js 18 or later only for the npx routes.
Bản source Odoo mà project đang chạy nằm trên máy, thêm enterprise nếu bạn dùng; Python 3.8 trở lên cho helper, chỉ dùng thư viện chuẩn nên virtualenv của Odoo là đủ; PostgreSQL có quyền tạo database scratch_* để chạy test; Node.js 18 trở lên chỉ khi cài bằng npx.
Will it touch my database or send my code anywhere?Nó có đụng vào database hay gửi code đi đâu không?
The trace helper only reads files and makes no network calls. Tests run on a throwaway scratch_<module> database that is dropped afterwards, and the assistant is told never to install or upgrade on a named database unless you ask. What your assistant sends to its model is up to the assistant.
Helper trace chỉ đọc file và không gọi mạng. Test chạy trên database scratch_<module> dùng xong bỏ, và trợ lý được dặn không bao giờ cài hay nâng cấp trên database có tên trừ khi bạn yêu cầu. Trợ lý gửi gì cho model là do trợ lý quyết định.
How is it better than asking the AI directly?Hơn gì so với hỏi AI trực tiếp?
Without it, the assistant answers from memory: fields that don't exist, such as sale.order.delivery_date, xpaths that stop the install, "tests pass" when no test ran. With it, every symbol gets a file:line or NOT FOUND before any code is written, and the change is proven on a scratch database. A blind grader preferred it 16 times to 6 over 32 pairs.
Không có nó, trợ lý trả lời theo trí nhớ: field không tồn tại như sale.order.delivery_date, xpath làm cài module lỗi, "test pass" khi chưa test nào chạy. Có nó, mọi symbol đều có file:line hoặc NOT FOUND trước khi viết code, và thay đổi được kiểm chứng trên database thử. Người chấm mù chọn nó 16 lần, so với 6, trên 32 cặp.
